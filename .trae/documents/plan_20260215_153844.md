# Fix MongoDB Replica Set Configuration

I will fix the issues preventing the MongoDB Replica Set from initializing correctly. The main issues are:
1.  **Primary Node Entrypoint Override**: The primary node is running the init script *instead of* the `mongod` process, so no database is actually running.
2.  **Missing Keyfile**: Replica sets with authentication enabled require a keyfile for internal node-to-node communication.
3.  **Initialization Logic**: The initialization script is currently trying to run inside the primary container (which isn't running mongod), instead of running alongside it.

## 1. Generate Keyfile
I will generate a secure keyfile for internal authentication.
-   Create `mongodb/replica-set/keyfile` with random content.
-   **Important**: I will set its permissions to `400` (read-only by owner) as required by MongoDB.

## 2. Update `docker-compose.yml`
I will rewrite `mongodb/replica-set/docker-compose.yml` to:
-   **Primary Node**: Remove the custom `entrypoint`. Use the standard `mongod` command with `--replSet rs0 --keyFile /data/keyfile --bind_ip_all`. Mount the keyfile.
-   **Secondary Nodes**: Update to use the same `command` and mount the keyfile.
-   **Setup Container**: Add a new, ephemeral `mongodb-setup` service. This container will:
    -   Mount the `init-replica.sh` script.
    -   Depend on the primary node.
    -   Run the script to initiate the replica set and then exit (it doesn't need to stay running).

## 3. Update `init-replica.sh`
I will improve the initialization script to:
-   Loop and wait until `mongodb-primary` is reachable (connection check).
-   Run `rs.initiate()` only once the primary is ready.
-   Remove the `tail -f /dev/null` since this script now runs in a temporary setup container.

## 4. Verify Fix
I will run the test runner: `python3 run_tests.py`. It should pick up where it left off (`mongodb/replica-set`) and verify the fix.
