# 创建增量式自动化测试系统

您说得对，当前的脚本确实让您进行了重复劳动。我将为您设计一个**增量式 (Incremental) 测试方案**，确保：
1.  **记录进度**：测试通过的服务会自动记录，下次运行时直接跳过。
2.  **强制清理**：无论测试成功与否，都会执行 `docker-compose down -v` 清理环境，为下一个测试做好准备。
3.  **断点续测**：脚本出错停止后，修复问题再次运行，会自动从失败点继续，而不是从头开始。

## 1. 核心逻辑 (`run_tests.py`)
我将创建一个 Python 脚本 `run_tests.py` 来替代 Shell 脚本，以获得更好的状态管理能力。

### 功能设计：
-   **状态文件 (`test_status.json`)**: 记录每个 `docker-compose.yml` 的测试结果（`pending`, `passed`, `failed`）。
-   **初始化**: 首次运行时扫描所有配置文件，生成初始状态列表。
-   **执行循环**:
    -   读取状态文件。
    -   跳过状态为 `passed` 的服务。
    -   对 `pending` 或 `failed` 的服务执行测试：
        1.  **Pre-cleanup**: 强制清理残留容器（防止端口冲突）。
        2.  **Up**: 启动服务。
        3.  **Check**: 验证状态。
        4.  **Post-cleanup (关键)**: **无论成功与否，立即销毁服务**。
        5.  **Save**: 如果成功，更新状态为 `passed` 并写入文件；如果失败，更新为 `failed` 并**立即退出**。

## 2. 使用流程
1.  运行 `python3 run_tests.py`。
2.  脚本自动跳过已通过的测试，直接运行未通过的测试。
3.  遇到错误 -> 脚本停止 -> 您修复配置。
4.  再次运行 `python3 run_tests.py` -> 脚本从刚才修复的服务继续测试。
5.  如果需要重测所有服务，运行 `python3 run_tests.py --reset`。

## 3. 执行计划
1.  删除旧的 `validate_runtime.sh`。
2.  创建 `run_tests.py`。
3.  运行脚本开始测试。
