## 1. PostgreSQL HA (`postgresql/ha/docker-compose.yml`)
I will replace the current file with a clean **Bitnami Replication Manager** setup.
-   **Images**: `bitnami/postgresql-repmgr:16` and `bitnami/pgbouncer:latest`.
-   **Architecture**:
    -   `pg-0` (Primary/Read-Write)
    -   `pg-1` (Standby/Read-Only)
    -   `pgbouncer` (Connection Pooler)
-   **Key Features**:
    -   Automatic failover via `repmgr`.
    -   No manual config files (`postgresql.conf`, `pg_hba.conf`) required; fully env-var driven.
    -   No root user or permission hacks needed.

## 3. Redis Sentinel (`redis/sentinel/docker-compose.yml`)
I will rewrite this using **Bitnami Redis Sentinel** images.
-   **Images**: `bitnami/redis:7.2` and `bitnami/redis-sentinel:7.2`.
-   **Architecture**:
    -   `redis-master`
    -   `redis-slave`
    -   `redis-sentinel` (x3)
-   **Why Bitnami?**: The official Redis image requires manual config files for Sentinel that are prone to IP/DNS issues (as we saw). Bitnami's images handle Sentinel configuration and master discovery automatically via environment variables (`REDIS_MASTER_HOST`, etc.).
