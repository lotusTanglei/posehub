# Create Multi-Architecture Compatibility Verification Plan

I will help you implement a strategy to verify compatibility across multiple environments (x86_64/AMD64 for servers, ARM64 for M-series/Raspberry Pi).

## 1. Create GitHub Actions Workflow (`.github/workflows/verify-compat.yml`)
The most effective way to test multi-arch compatibility without buying hardware is using CI/CD.
-   **Matrix Strategy**: I will create a workflow that runs your `run_tests.py` on multiple runners.
    -   `ubuntu-latest` (Standard x86_64 environment)
    -   `ubuntu-24.04-arm` (GitHub's new ARM64 runners, if available to you, or using QEMU emulation).
-   **QEMU Integration**: Since native ARM runners might be paid/limited, I will configure **QEMU** to emulate ARM64 on x86 runners, and vice-versa. This allows testing both architectures in one pipeline.
-   **Step**:
    1.  Checkout code.
    2.  Set up Docker Buildx (for multi-arch support).
    3.  Install Python dependencies.
    4.  Run `python3 run_tests.py`.

## 2. Enhance `run_tests.py` for CI
-   **CI Mode**: Add a `--ci` flag or detect `CI=true` environment variable.
-   **Behavior**: In CI mode, it should output logs more verbosely but perhaps fail faster or produce a JUnit XML report for the CI system to visualize.

## 3. Documentation (`COMPATIBILITY.md`)
I will create a guide explaining:
-   How to run local multi-arch tests using `docker buildx`.
-   Which images are known to be multi-arch (e.g., `postgres:alpine` is safe, `bitnami` can be tricky).
-   How to check image manifests manually (`docker manifest inspect`).

## 4. Execution
1.  Create the workflow file.
2.  Create the documentation.
3.  (Optional) Modify `run_tests.py` if needed for better CI integration.
